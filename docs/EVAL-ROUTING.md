## Method

1. A fresh Postgres + pgvector container; the six sample documents are ingested; the mock tracker is reached over HTTP through the app's own random port.
2. Each question goes through the full `/ask` pipeline: classification, routing, tools, answer, checks.
3. **Intent** compares the classifier's intent with the label (a low-confidence fallback still counts the classifier's own intent).
4. **Tracker calls** pass when every expected call appears in the tool-call log; a misrouted question that never reaches the tracker fails this check.
5. **Exact facts** pass when the answer was shown and contains every expected fact from the tracker data.
6. **Invented** re-checks every shown tracker answer against the full tracker data (not just what the tools returned): unknown tickets or tests, or a status that contradicts the ticket named in the same sentence.
7. Model output varies a little between runs; the labels are fixed.
